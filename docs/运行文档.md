## 1. 环境要求

| 项目 | 版本/说明 |
|------|-----------|
| 操作系统 | Ubuntu 22.04 LTS |
| ROS 2 | Humble Hawksbill（`/opt/ros/humble`） |

> ```
> 若缺包，用 `sudo apt install ros-humble-<包名>` 安装。

## 2. 工作区结构与首次构建

### 2.1 工作区根目录

本项目的 colcon 工作区根目录就是 **`/home/rostwo/nav2xuexi/sam_bot_description/`**，它同时也是一个 ROS 包（`sam_bot_description`），`build/`、`install/`、`log/` 三个构建产物目录就在它内部：

```
/home/rostwo/nav2xuexi/sam_bot_description/      # ← 工作区根 + 包根（二合一）
├── CMakeLists.txt  package.xml                   # 包元数据
├── src/
│   ├── description/sam_bot_description.urdf      # 机器人模型（xacro）+ Gazebo 插件
│   ├── launch/navigation.launch.py               # 完整导航启动
│   ├── launch/display.launch.py                  # 模型+仿真显示启动（无 Nav2）
│   ├── config/nav2_params.yaml                   # Nav2 全部参数
│   ├── config/ekf.yaml                           # EKF 融合参数
│   ├── rviz/urdf_config.rviz                     # 模型显示用 RViz 配置
│   ├── world/my_world.sdf                        # 世界（围墙 + 障碍物）
│   └── behavior_trees/*no_backup.xml             # 去除 BackUp 的自定义行为树（备选）
├── map/my_map.yaml + my_map.pgm                  # 预建静态地图
├── docs/                                         # 各类文档
├── build/  install/  log/                        # colcon 构建产物
```

> ⚠️ 注意工作区根是 `sam_bot_description` 本身，**不是**它的上一级 `/home/rostwo/nav2xuexi`。构建和 source 都要在这个目录里进行。

### 2.2 首次构建

```bash
cd /home/rostwo/nav2xuexi/sam_bot_description

# 用 --symlink-install：config/description 等文件装成符号链接，
# 之后改源码里的 yaml/urdf 不用重新 build 就能生效（无需编译 C++）
colcon build --symlink-install

# 让当前终端能找到装好的包
source install/setup.bash
```

> 每个新终端都要重新 `source /opt/ros/humble/setup.bash` 和 `source install/setup.bash`。

## 3. 启动项目

### 3.1 完整导航仿真（推荐）

一次启动 **Gazebo（世界+机器人）+ EKF + 完整 Nav2 导航栈 + RViz**：

```bash
cd /home/rostwo/nav2xuexi/sam_bot_description
source /opt/ros/humble/setup.bash
source install/setup.bash

# ↓ 本机（Ubuntu 22.04 + 该 Qt/GL 环境）需要的两个环境变量，见 6.4 节
export GSETTINGS_SCHEMA_DIR=/home/rostwo/.local/share/glib-2.0/schemas
export QT_QPA_PLATFORM=xcb

ros2 launch sam_bot_description navigation.launch.py
```

`navigation.launch.py` 依次拉起：

```
gzserver（加载 src/world/my_world.sdf）
gzclient（Gazebo 图形界面）
robot_state_publisher（xacro 展开 URDF → 发布 base_link→* 的静态 TF）
spawn_entity（把机器人 spawn 进 Gazebo）
ekf_filter_node（robot_localization，融合 odom+IMU → 发布 odom→base_link TF）
nav2_bringup / bringup_launch.py（map_server / AMCL / planner / controller / BT ...）
rviz2（加载 Nav2 官方默认视图 nav2_default_view.rviz）
```

### 3.2 只显示模型与仿真（无导航）

启动 **Gazebo + 机器人 + EKF + RViz**，但不启动 Nav2 导航栈，可用于检查模型/传感器/仿真本身：

```bash
cd /home/rostwo/nav2xuexi/sam_bot_description
source /opt/ros/humble/setup.bash
source install/setup.bash
export GSETTINGS_SCHEMA_DIR=/home/rostwo/.local/share/glib-2.0/schemas
export QT_QPA_PLATFORM=xcb

ros2 launch sam_bot_description display.launch.py
# 参数： gui:=False（启用命令行版 joint_state_publisher，而非 GUI 版）
```

`display.launch.py` 用 `gazebo --verbose`（GUI+server 合体）、`robot_state_publisher`、`spawn_entity`、`ekf_filter_node` 和加载 `urdf_config.rviz` 的 `rviz2`，不含 Nav2。

## 4. 运行后的操作流程

启动完成后，导航栈会自动配置并激活。此时还差两步人工操作，机器人才能动起来：

### 4.1 给 AMCL 设置初始位姿（必须）

AMCL 是粒子滤波定位，**不知道机器人初始在哪**，必须先给一个初始估计，它才会发布 `map→odom` 变换。在 RViz 里：

1. 工具栏点 **2D Pose Estimate**（绿色箭头图标）；
2. 在地图上机器人实际所在位置**点一下**（定位置），**按住拖动再松开**（定朝向）。

完成后 RViz 里的激光点云会**对齐到地图墙线**，说明定位成功。终端里 AMCL 从 `AMCL cannot publish a pose or update the transform. Please set the initial pose...` 变成正常发布 `map→odom`。

> 机器人默认 spawn 在 Gazebo 世界原点 (0,0)，对应地图坐标约 (0,0)，所以初始位姿通常点在地图中心附近。若机器人已被移动到别处，请按实际位置点。

### 4.2 下发目标点

1. 工具栏点 **2D Nav Goal**（紫色箭头图标）；
2. 在地图上点目标位置并拖出期望朝向。

机器人随即开始：全局规划（NavFn）→ 局部跟踪（MPPI）→ 到达后原地摆正到目标朝向 → `Goal succeeded`。

### 4.3 判断是否成功

- 终端出现 `[controller_server] Reached the goal!` 和 `[bt_navigator] Goal succeeded`。
- 机器人停在目标点（误差 < `xy_goal_tolerance`，默认 0.25 m）并把朝向摆到目标朝向（误差 < `yaw_goal_tolerance`，默认 0.25 rad）。

## 5. 验证与调试命令

```bash
# 已启动的节点
ros2 node list

# TF 树是否完整（map→odom→base_link→lidar_link 等）
ros2 run tf2_ros tf2_echo map base_link
ros2 run tf2_ros tf2_echo odom base_link

# 话题是否在发
ros2 topic list
ros2 topic echo /scan --once          # 激光
ros2 topic echo /demo/odom --once     # 里程计
ros2 topic echo /demo/imu --once      # IMU
ros2 topic hz /scan                    # 激光频率（应约 15 Hz）

# EKF 融合后的里程计（odom→base_link）
ros2 topic echo /odometry/filtered --once

# 定位结果
ros2 topic echo /amcl_pose --once

# 各 action server 是否就绪
ros2 action list

# 手动下发一个目标（不依赖 RViz）
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 2.0, y: 2.0, z: 0.0}, orientation: {w: 1.0}}}}"

# 查看节点参数（例如确认 use_sim_time）
ros2 param get /amcl use_sim_time
```

## 6. 常见问题排查

### 6.1 导航栈起不来 / 报 `class ... does not exist`

```
Failed to create global planner. Exception: ... class nav2_navfn_planner::NavfnPlanner
with base class type nav2_core::GlobalPlanner does not exist. Declared types are nav2_navfn_planner/NavfnPlanner ...
```

原因：`nav2_params.yaml` 里 `plugin:` 字段写错了。**Nav2 插件的查找键**分两种（详见 [说明文档.md §5.2](说明文档.md)）：

- 插件 XML **带 `name` 属性**的 → 用 `name`（斜杠），例如 `nav2_navfn_planner/NavfnPlanner`、`nav2_behaviors/Spin`；
- 插件 XML **只有 `type`** 的 → 用 C++ 类名（双冒号），例如 `nav2_mppi_controller::MPPIController`、`nav2_controller::SimpleGoalChecker`、代价地图各层。

### 6.2 `parameter 'yaml_filename' is not initialized`（map_server 起不来）

`nav2_params.yaml` 里 `map_server.ros__parameters.yaml_filename` 被注释掉了。启动时 Nav2 的 `RewrittenYaml` 只**改写已存在的键**，不会凭空注入，所以这个键必须存在（哪怕是空字符串 `""`）。

### 6.3 下发目标后机器人不动 / 瞬间 `Reached the goal!` / `Transform data too old`

根因通常是 **`use_sim_time` 缺失**：`nav2_params.yaml` 的每个 `ros__parameters` 段都必须有 `use_sim_time`（本文件共 15 处）。一旦缺失，Nav2 节点用墙钟时间、Gazebo 用 `/clock` 仿真时间，两者对不上，表现为：

- `Transform data too old when converting from map to odom`；
- 目标刚下发就 `Reached the goal!`，但车根本没动。

确认方法：`grep -c use_sim_time src/config/nav2_params.yaml` 应等于 15。

> 另一个易混淆的瞬时现象：**启动初期** EKF 要收到首帧 odom+IMU 才开算、且 gzserver 加载世界时吃满 CPU，会出现短暂的 `Timed out waiting for transform`、`Failed to meet update rate` 和 TF `unconnected trees`，这些会随 EKF 输出 `odom→base_link` 后自动消失，不是故障。

### 6.4 rviz2 / joint_state_publisher_gui 启动即崩溃（本机专属）

本机（Ubuntu 22.04 + gnome-settings-daemon 42 + Qt GTK 主题）上，rviz2 会因 `GLib-GIO-ERROR: ... 'antialiasing'` 崩溃。**启动前必须 export**：

```bash
export GSETTINGS_SCHEMA_DIR=/home/rostwo/.local/share/glib-2.0/schemas
export QT_QPA_PLATFORM=xcb
```

另：rviz2 偶发 `GLSL link result` 报错和段错误（exit -11）属于本机 OGRE/Mesa 老问题，**不影响导航本身**——rviz2 崩了之后 `component_container`（导航栈）+ Gazebo 仍在正常跑。

### 6.5 机器人到目标点后摆不正 / 原地转不动

先确认不是定位发散（见 6.6），再检查：

- 目标检查器容差：`general_goal_checker` 的 `yaw_goal_tolerance`（当前 0.25 rad）；
- 局部控制器是否允许原地旋转：MPPI 的 `wz_max`（当前 1.9）、`PreferForwardCritic` / `GoalAngleCritic` 权重；
- 机器人是否被卡在恢复循环里（日志反复出现 `Collision Ahead - Exiting Spin`），那通常是 AMCL 定位跑偏导致代价地图把可行区域当成了障碍。

### 6.6 AMCL 定位发散（车已到点但地图里位置漂了）

特征：`/demo/odom` 里车已到目标，但 `/amcl_pose` 显示的位置与真实差好几米。

处理：在 RViz 重新用 **2D Pose Estimate** 给一个正确初始位姿，或重启后重设。定位质量还受 AMCL 参数（`min_particles`/`max_particles`/`alpha1~5`）和激光量程（3.5 m）影响。

### 6.7 改了 yaml/urdf 不生效

- 改了 `nav2_params.yaml` / `ekf.yaml` / `urdf` / `sdf`：`--symlink-install` 下是软链接，**重新 launch 即可生效**（无需 rebuild）。
- 若当初是用普通 `colcon build`（非 symlink）装的，改了这些文件要重新 `colcon build --symlink-install` 才会复制进 install。

### 6.8 启动时报找不到包 / 找不到 launch 文件

先确认在 `/home/rostwo/nav2xuexi/sam_bot_description` 目录下 `source install/setup.bash`；若仍报错，回到 2.2 重新 `colcon build --symlink-install`。
