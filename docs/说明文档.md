## 1. 项目全景

一个**差速轮式移动机器人**在 Gazebo 里的完整导航仿真，技术栈：

```
URDF/xacro 机器人模型
   │  xacro 展开
   ▼
robot_state_publisher ──► 静态 TF（base_link → 各 link）
   │
   ▼  spawn 进 Gazebo
Gazebo 插件 ──► /demo/odom（轮式里程计）、/livox/imu、/livox/lidar（点云）
   │
   ▼
FAST-LIO ──► /Odometry + odom → base_link TF（LiDAR + IMU 紧耦合）
   │
   ▼
Nav2 ──► map_server(2D 静态地图) + fastlio_relocalization(3D 重定位)
         + planner(全局规划) + controller(局部跟踪) + BT(编排)
   │
   ▼
/cmd_vel ──► Gazebo diff_drive 驱动轮子
```

本项目是标准 colcon 工作区，含**四个包**：`sam_bot_description`（机器人描述 + 导航配置）、`mid360_simulation`（Mid-360 仿真插件）、`fast_lio`（LiDAR+IMU 紧耦合里程计 FAST-LIO）和 `fastlio_localization`（基于先验 PCD 的 3D 点云重定位，替代 AMCL）。导航栈使用 Nav2 官方插件，里程计由 FAST-LIO 提供：

| 环节 | 插件 |
|------|------|
| 全局规划 | `nav2_navfn_planner/NavfnPlanner`（NavFn / Dijkstra） |
| 局部控制 | `nav2_mppi_controller::MPPIController`（MPPI 采样） |
| 定位 | `fastlio_localization/relocalization_node`（C++，PCL 全局搜索 + ICP，发布 map→odom） |
| 里程计 | FAST-LIO（`fast_lio`，LiDAR+IMU 紧耦合，发布 odom→base_link） |
| 恢复行为 | `nav2_behaviors`（Spin / BackUp / DriveOnHeading / Wait / AssistedTeleop） |
| 建图（离线） | 2D：`slam_toolbox`（`online_async`）；3D：FAST-LIO `pcd_save`（`build_3d_map.sh`） |

> **地图是两条离线链路**：
> 1. **2D 栅格图**（`map/my_map.yaml` + `.pgm`）：`build_map.sh` 启动 `display.launch.py` 再起 `slam_toolbox online_async`，键盘遥控建图，结束用 `map_saver_cli` 保存。它只给 Nav2 的 `global_costmap` 的 static_layer 使用。
> 2. **3D 先验点云**（`map/prior_3d_map.pcd`）：`build_3d_map.sh` 用 FAST-LIO 的 `pcd_save_en` + `/map_save` 把 odom 系累积点云写成 PCD，供 3D 重定位做 ICP。
>
> 导航运行期**没有任何 slam 节点**；定位完全来自 3D 配准（AMCL 已移除）。详见 §4.3、§5.2 与 [运行文档 §3.3/§3.4](运行文档.md)。

## 3. 硬件环境

### 3.1 机器人硬件平台（被仿真对象）

机器人 `sam_bot` 是一个 **1.05 × 0.74 × 1.08 m、约 33 kg** 的差速轮式移动底盘，模型来自 CAD 导出的 URDF + STL 网格，全部由 `src/sam_bot_description/description/sam_bot_description.urdf` 定义（xacro 展开），网格在 `meshes/visual/`。Gazebo 里的每个 `<gazebo>` 段就是一个"虚拟硬件"及其驱动插件。

#### 3.1.1 车体与整体参数

| 项 | 值 | 说明 |
|----|-----|------|
| 车体尺寸（长×宽×高） | 1.05 × 0.67 × 1.08 m | `base_chassis` 的 CAD 网格包络（含车轮总宽约 0.74 m） |
| 车体质量 | 28.11 kg | CAD 直接给出的质量与惯量 |
| 整机质量 | ≈33 kg | 车体 + 2 驱动轮 + 2 万向轮组件 + 相机 |
| 导航基准点 | `base_footprint` | `base_link` 正下方 0.24 m（驱动轮最低点），2D 代价地图用它定位 |
| CAD 坐标系 | `base_chassis` | 原生 Y 朝前；用 `chassis_joint` 绕 Z 转 −90° 挂到 `base_link` 下 |

#### 3.1.2 驱动系统（差速驱动）

| 项 | 值 | 说明 |
|----|-----|------|
| 驱动方式 | 差速（differential drive） | 2 个后置驱动轮 + 2 个前置万向轮（转向+滚动均为被动 continuous 关节） |
| 轮子半径 / 直径 | 0.10 m / 0.20 m | 驱动轮；万向轮半径 0.04 m |
| 轮距（wheel_separation） | 0.481 m | 两驱动轮中心横向间距 |
| 轮子安装位置 | CAD 坐标 x=±0.24 m, y=−0.32 m | 旋转后位于 `base_link` 后部两侧（x≈−0.32, y=±0.24） |
| 最大轮扭矩 | 30 N·m | `max_wheel_torque` |
| 最大轮角加速度 | 3.0 rad/s² | `max_wheel_acceleration` |
| 前进速度上限 | 0.5 m/s（后退 −0.35 m/s） | 由 Nav2 MPPI `vx_max/vx_min` 约束 |
| 角速度上限 | 1.9 rad/s | Nav2 MPPI `wz_max` |

执行器插件 `libgazebo_ros_diff_drive.so`：订阅 `/cmd_vel`（Twist），把 `vx/wz` 换算成左右轮转速；发布 `/demo/odom`，并且 **`publish_odom_tf=false`**（odom→base_link 的 TF 交给 FAST-LIO 发，避免重复发布同一 TF）。`/demo/odom` 只保留给 Nav2 controller/velocity_smoother 读速度反馈。

> **万向轮策略（重要，别再改回去）**：两个万向轮（`new_link_3`/`new_link_5`）半径 0.04 m，轮心高度使最低点**比地面高约 2 mm（悬空）**，关节 `damping="0.2" friction="0.2"`，Gazebo 摩擦 `mu1/mu2=0.1`。
> 曾经尝试「万向轮着地 + 低摩擦」，结果 CAD 万向轮有前倾偏移量（trail），运动时轮架把车头**顶起 7.7 cm**（真值 z 从 0.2399 升到 0.3166），进而不稳。悬空时由两个驱动轮承担全部地面接触，直行/转向都稳定。详见 `sam_bot_description.urdf` 第 5 节注释。
>
> **已知残余现象**：两个驱动轮由 `diff_drive` 插件驱动，`cmd_vel=0` 时插件只把目标轮速设为 0、不抱死，车体会缓慢滑行 **约 13 cm/min**（无指令仍匀速漂）。FAST-LIO 会实时跟随它，定位不受影响；如需车停得死，给驱动轮关节加大 `damping` 或另加抱死摩擦模型。详见 [运行文档 §6.14](运行文档.md)。

#### 3.1.3 传感器

| 传感器 | link / frame | 话题 | 频率 | 关键参数 |
|--------|-------------|------|------|----------|
| IMU | `livox_imu` | `/livox/imu` | 200 Hz | 内置于 Mid-360（BMI088）：角速度 stddev 1e-5、线加速度 stddev 1e-4；装在雷达内 (0.011, 0.02329, −0.04412) |
| 激光雷达 | `livox` | `/livox/lidar`（PointCloud2） | 10 Hz | 非重复扫描 3D 点云、量程 0.1~15.0 m、测距噪声 stddev 0.01 m；CAD 自带的雷达网格已从车体 STL 删除，仿真雷达装在原底座上 (0.346, 0, 0.93) m，**整条 link 按 CAD 斜面朝前进方向前倾 30°**（点云真实斜装）；为避免前倾后向下波束扫到车头横杠/前脸，整体抬高 0.051 m、倾角不变；IMU 坐标系反向旋回水平（`imu_rpy`），雷达相对 IMU 的 30° 由 FAST-LIO `extrinsic_R/T` 补偿 |
| 2D 激光（投影） | `base_link` | `/scan`（LaserScan） | 10 Hz | 由 `pointcloud_to_laserscan` 把 `/livox/lidar` 投影得到；高度窗口 −0.05~0.80 m，上限用于滤掉雷达自身安装平台的回波 |
| 深度相机 | `camera_depth_frame` | `/depth_camera/*` | 30 Hz | 640×480、水平 FOV 60°（1.047 rad）、量程 0.05~3 m、双目基线 0.2 m；装在车头前脸 (0.50, 0, 0.30) m |

> `/cloud_registered` 的 15.0 m 量程决定了 3D 重定位的对齐范围；FAST-LIO 用 LiDAR+IMU 紧耦合输出 odom→base_link，替代 EKF 修正纯轮式里程计的航向漂移；`/scan`（由 `/livox/lidar` 投影，同样 15 m）只给 Nav2 代价地图使用。
>
> **IMU 与 base_link 的偏移**：FAST-LIO 内部状态是 IMU 体坐标系的位姿，而 URDF/Nav2 的基准是 `base_link`。IMU 装在 `base_link` 前上方 **(0.3335, 0.0233, 0.8863) m**（`livox` 的 +30° 与 `livox_imu` 的 −30° 姿态互相抵消，R=I）。`laserMapping.cpp` 的 `set_posestamp()` 用 `mapping.body_to_base_T/R` 做 `T_world_base = T_world_imu · T_base_imu⁻¹` 换算后再发布 `odom→base_link` 与 `/Odometry`，否则 RViz/Nav2 足迹会整体前移 0.33 m，出现"RViz 没撞、Gazebo 撞了"。
>
> **Mid-360 仿真注意点**（`mid360.xacro`）：
>
> - 射线传感器必须带 `<always_on>true</always_on>` 才会持续发点云（缺失时 `/livox/lidar` 几乎静默）。
> - `point_rate=200000` 必须保留：它决定每帧覆盖的方位角范围（200000/10 = 20000 个方位点 ≈ 360° 全向）。若把 point_rate 降到两万，每帧只覆盖 ~51° 扇形，FAST-LIO 报 "Too few input point cloud!"。
> - 实际射线数由 `<downsample>` 控制：`samples = 20000`，射线数 = 20000 / downsample。当前 **downsample=8 → 2500 条射线 → 约 590 个有效点/帧**（10 Hz）。
> - **不要低于 8**：downsample=5（4000 条）会让 gzserver 在 `libgazebo_ode.so` 内空指针崩溃（SIGSEGV，`exit -11`），已稳定复现；详见 [运行文档 §6.12](运行文档.md)。

## 4. 仿真世界与地图

### 4.1 世界（`src/sam_bot_description/world/my_carpark`）

默认场景是约 **20×20 m 的停车场**：四周 2.5 m 高围墙，内部有隔墙、隔离墩，以及两辆静止车辆（`suv`、`hatchback_red`）。机器人出生在 **(2.0, 2.7)**——`display.launch.py` 与 `navigation.launch.py` 的 spawn 参数一致，建图和导航才能共用同一个 `map` 原点。

> 该文件是从 Gazebo 直接保存的完整 world，**文件名没有 `.sdf` 后缀**，gzserver 按内容解析。
> 其它场景保留在 `world/` 下，改 launch 里的 `world_path` 即可切换：
> - `my_world.sdf`：10×10 m 方围墙 + `unit_box`（1×1×1 m）+ `unit_sphere`（半径 0.5 m）；
> - `my_newworld.sdf`：建模导出的楼宇（配套 `model.sdf` / `model.config`）。

地面摩擦 μ=1.0，重力 −9.8，物理引擎 ODE（`max_step_size 0.001`、`real_time_update_rate 1000`）。

### 4.2 地图（`src/sam_bot_description/map/my_map.yaml` + `my_map.pgm`）

| 项 | 值 | 含义 |
|----|-----|------|
| `image` | `my_map.pgm` | 占用栅格图像（**必须是同目录下真实存在的文件名**） |
| `resolution` | 0.05 | 每像素 5 cm |
| `origin` | `[-13.0481, -13.2706, 0]` | 地图左下角在 map 坐标的位置（随每次建图略有变化） |
| `mode` | `trinary` | 三值（占用/自由/未知） |
| `occupied_thresh` / `free_thresh` | 0.65 / 0.25 | 占用/自由判定阈值 |

地图约 **420×426 像素**（0.05 m/pix），覆盖约 **21.0 m × 21.3 m**，对应 `[-13.05, 7.95] × [-13.27, 8.03]`（map 坐标）。`map` 原点是**建图起点的 IMU 位姿**，不是 Gazebo 世界原点，所以不要拿世界坐标直接对照。`origin` 和尺寸由保存脚本按本次建图的实际范围自动写入，重新建图后会变。

### 4.3 建图流程（`build_map.sh`，默认 RTAB-Map）

导航用的是**离线建好的静态地图**。需要重新建图时走另一条链路，与导航链路互斥：

```
Gazebo（/livox/lidar 点云 + /livox/imu）
   │
   ├──► FAST-LIO（2D 建图配置 mid360_sim_2dmap.yaml）──► odom → base_link TF
   │
   └──► pointcloud_to_laserscan ──► /scan（2D）
                                        │
                                        ▼
                            rtabmap_mapping.launch.py（默认）
                            ├── 栅格建图（/scan + FAST-LIO 里程计）
                            ├── 发布 /map
                            └── 发布 map → odom TF
                                        │
键盘遥控 /cmd_vel ───────────────────────┘
按 Ctrl+C ──► tools/save_map.py ──► map/my_map.yaml + my_map.pgm
```

`SLAM_ALGO=slam_toolbox ./build_map.sh` 可切回 slam_toolbox；下面这张表是 slam_toolbox 分支的参数（`config/mapper_params_online_async.yaml`）：

| 参数 | 值 | 说明 |
|------|-----|------|
| `odom_frame` / `map_frame` / `base_frame` | `odom` / `map` / `base_footprint` | 与本项目 TF 树一致 |
| `scan_topic` | `/scan` | 由 Mid-360 点云投影得到 |
| `max_laser_range` | 15.0 | 与 Mid-360 量程一致（官方默认 20.0） |
| `transform_timeout` | **1.0** | 见下方说明；官方默认 0.2 不够 |
| `scan_queue_size` | **30** | 扫描消息队列深度，防止等 TF 时溢出丢帧 |

> **为什么 `transform_timeout` 要放大到 1.0**：FAST-LIO 发布 `odom→base_link` 比 `/scan` 晚约 0.2 s（要先处理完点云）。`slam_toolbox` 的 `tf2_ros::MessageFilter` 拿到一帧扫描后，会在**该扫描的时间戳**上查 TF，查不到就排队等；默认 `transform_timeout: 0.2` + 很小的队列，会持续打印
> `Message Filter dropping message: frame 'base_link' ... queue is full` 并丢掉绝大多数扫描——表现是**地图几乎不更新**（车开了几米地图只多几格）。

## 5. Nav2 配置详解

文件：`src/sam_bot_description/config/nav2_params.yaml`，共 **15 个 `ros__parameters` 段**，每段都带 `use_sim_time: True`（**必须**，见 [运行文档 §6.3](运行文档.md)）。

### 5.1 插件命名规则（`::` vs `/`）

Nav2 加载插件时，`plugin:` 字段的查找键取决于**插件 XML 是否带 `name` 属性**：

| 插件 | `plugin:` 该写 | 依据 |
|------|---------------|------|
| `nav2_navfn_planner/NavfnPlanner` | 斜杠 | 官方 XML 有 `name` |
| `nav2_behaviors/Spin`（BackUp/DriveOnHeading/Wait/AssistedTeleop 同） | 斜杠 | 官方 XML 有 `name` |
| `nav2_mppi_controller::MPPIController` | 双冒号 | 官方 XML 只有 `type` |
| `nav2_controller::SimpleGoalChecker` / `SimpleProgressChecker` | 双冒号 | 同上 |
| `nav2_costmap_2d::ObstacleLayer` 等代价图层 | 双冒号 | 同上 |
| `nav2_smoother::SimpleSmoother` | 双冒号 | 同上 |
| `nav2_waypoint_follower::WaitAtWaypoint` | 双冒号 | 同上 |

规则：**看插件 XML 里有没有 `<class name="...">`**——有 `name` 就用 `name`（斜杠），只有 `type` 就用 `type`（双冒号）。写错报 `class ... does not exist. Declared types are ...`。

### 5.2 fastlio_relocalization（3D 重定位，替代 AMCL）

配置：`src/fastlio_localization/config/relocalization_params.yaml`，节点由 `navigation.launch.py` 启动。AMCL 及其粒子滤波参数已从 `nav2_params.yaml` 删除。

| 参数 | 值 | 含义 |
|------|-----|------|
| `prior_map_path` | `map/prior_3d_map.pcd` | 先验 3D 点云（FAST-LIO 建图产物，坐标系 = map） |
| `scan_topic` | `/cloud_registered` | FAST-LIO 输出的去畸变点云（odom 系） |
| `map_frame` / `odom_frame` / `base_frame` | `map` / `odom` / `base_link` | ICP 求出的就是 `map→odom` |
| `map_voxel_size` / `scan_voxel_size` | 0.15 / 0.20 m | 先验地图与实时帧的体素下采样 |
| `global_scan_voxel_size` | 0.45 m | 全局搜索用的更稀疏帧（降耗时） |
| `min/max_scan_range` | 0.5 / 15.0 m | 滤掉车体回波、与雷达量程一致 |
| `icp_max_iterations` | 30 | ICP 迭代上限 |
| `icp_corr_dist_tracking` / `_relocalize` | 0.7 / 1.5 m | 跟踪 / 重定位阶段的最大对应距离 |
| `inlier_distance` | 0.35 m | 最近邻小于它算内点 |
| `min_inlier_ratio` | **0.55** | 内点率低于此判为失败（连续失败 5 帧触发重新全局搜索） |
| `relocalize_fail_count` | 5 | 连续失败帧数阈值 |
| `max_tracking_jump` / `_yaw_jump` | 1.0 m / 0.6 rad | 单帧结果跳变保护，超限则丢弃该帧 |
| `correction_alpha` | 0.6 | 输出平滑系数（1.0 = 不平滑） |
| `constrain_planar` | `true` | 地面机器人：`map→odom` 只保留 x/y/yaw |
| `relocalize_on_start` | `true` | 启动即做一次全局搜索（无需手动给初始位姿） |
| `global_search_xy_step` / `_yaw_step_deg` | 0.5 m / 15° | 粗搜索栅格 |
| `global_search_top_k` | 8 | 粗搜索取前 K 个候选做 ICP 精配准 |
| `global_search_height` | **0.35 m** | 只用“地图最高点以下 0.35 m 内”的高处结构评分，抑制对称歧义（见下） |
| `publish_rate` | 10 Hz | `map→odom` TF 发布频率 |
| `tf_future_stamp` | 0.2 s | TF 时间戳超前量，避免 Nav2 查 TF 报 extrapolation into the future |
| `publish_aligned_scan` | `true` | 额外发布 `/aligned_scan` 方便 RViz 检查配准效果 |

> **`global_search_height` 是解决“转 90° 也像”的关键**：仿真点云里大部分点落在地面与墙脚，地面在 (x, y, yaw) 上平移/旋转不变，会把“转了 90° 仍然贴着墙”的对称解分数抬高。本项目实测曾出现 `map→odom = (−1.90, −2.33, −31°)` 的别名解，与真值 (1.84, −1.71, 57°) 差约 3.9 m，且别名解的均方最近邻距离（0.093）比真值（0.159）还小。把评分点限制到墙顶/箱顶/球顶这段高处结构后，真值稳定胜出；当第二候选分数 ≥ 最优的 90% 且位姿不同时，节点还会打印歧义告警。设 `<= 0` 可关闭该过滤。

### 5.3 controller_server（局部控制，MPPI）

```yaml
controller_frequency: 20.0
controller_plugins: ["FollowPath"]
FollowPath:
  plugin: "nav2_mppi_controller::MPPIController"
  time_steps: 56;  model_dt: 0.05    # 2.8 s 前瞻
  batch_size: 2000                   # 采样轨迹条数
  vx_max: 0.5;  vx_min: -0.35        # 线速度范围（负值允许后退）
  wz_max: 1.9                        # 角速度上限
  motion_model: "DiffDrive"
  temperature: 0.3;  gamma: 0.015
  critics: [ConstraintCritic, CostCritic, GoalCritic, GoalAngleCritic,
            PathAlignCritic, PathFollowCritic, PathAngleCritic, PreferForwardCritic]
```

- `CostCritic` 用足迹做碰撞检测（`consider_footprint: true`、`critical_cost: 300`）；
- `GoalAngleCritic` + `PreferForwardCritic` 保证到点后摆正朝向；
- 目标检查器 `general_goal_checker`：`xy_goal_tolerance: 0.25`、`yaw_goal_tolerance: 0.25`、`stateful: True`。

### 5.4 planner_server（全局规划，NavFn）

```yaml
planner_plugins: ["GridBased"]
GridBased:
  plugin: "nav2_navfn_planner/NavfnPlanner"
  tolerance: 0.5
  use_astar: false      # Dijkstra
  allow_unknown: true
```

### 5.5 两个代价地图

| | global_costmap | local_costmap |
|--|----------------|---------------|
| 坐标系 | `map` | `odom`（滚动窗口） |
| 尺寸 | 整图 | 3×3 m 窗口，分辨率 0.05 |
| 图层 | static + obstacle + inflation | voxel + inflation |
| 障碍观测 | `/scan` | `/scan` |
| 膨胀 | `inflation_radius: 0.55`、`cost_scaling_factor: 3.0` | 同左 |
| 足迹 | `[[0.55,0.38],[0.55,-0.38],[-0.54,-0.38],[-0.54,0.38]]` | 同左（矩形，按 CAD 网格包络外扩 1~2 cm） |

> **足迹必须用矩形，不要用 `robot_radius`**：新 CAD 车体约 1.05 m(长) × 0.74 m(宽)，旧值 `0.42 × 0.39` 是给小机器人设的，会让规划器以为可以贴墙太近、实际车身撞障碍。global 与 local 两张图现在用同一个矩形足迹。

### 5.6 behavior_server（恢复行为）

```yaml
behavior_plugins: ["spin", "backup", "drive_on_heading", "assisted_teleop", "wait"]
```

`spin` 原地旋转、`backup` 后退、`wait` 等待等，供行为树在卡住时触发恢复。注意：默认行为树里的 `BackUp` 节点依赖这里的 `backup` action server（若移除 `backup` 需改用 `src/sam_bot_description/behavior_trees/*no_backup.xml`）。

### 5.7 velocity_smoother（速度平滑）

`controller_server` 发布 `/cmd_vel_nav` → `velocity_smoother` 限幅平滑后发 `/cmd_vel` → Gazebo。参数：`max_velocity [0.5, 0, 2.0]`、`min_velocity [-0.5, 0, -2.0]`、`max_accel [2.5, 0, 3.2]` 等。

### 5.8 其余段

| 段 | 说明 |
|----|------|
| `bt_navigator` | 编排导航（`NavigateToPoseNavigator` / `NavigateThroughPosesNavigator`），`odom_topic: /demo/odom` |
| `map_server` | 加载静态地图（`yaml_filename` 启动时被 bringup 的 `map` 参数改写） |
| `map_saver` | 保存地图 |
| `smoother_server` | `SimpleSmoother`，平滑全局路径 |
| `waypoint_follower` | 多航点任务（`WaitAtWaypoint`，每点停 200 s） |
| `collision_monitor` / `docking_server` / `loopback_simulator` | 参数文件里有配置段，但**默认 bringup 不加载** |

## 6. 坐标关系与数据流

### 6.1 TF 树

```
map ──► odom ──► base_link ──► base_footprint
                     ├──► base_chassis ──► new_link / new_link_1          （驱动轮）
                     │                 └──► new_link_2/4 ──► new_link_3/5（万向轮）
                     ├──► livox ──► livox_imu
                     └──► camera_link ──► camera_depth_frame
```

| TF | 发布者（导航时） | 发布者（建图时） |
|----|------------------|------------------|
| `map → odom` | fastlio_relocalization（点云对先验 PCD 做 ICP） | 2D 建图：slam_toolbox；3D 建图：无（odom 即 map） |
| `odom → base_link` | FAST-LIO（`/livox/lidar` + `/livox/imu` 紧耦合） | FAST-LIO |
| `base_link → 各 link` | robot_state_publisher（URDF） | robot_state_publisher |

> `map→odom` 的发布者**同时只能有一个**。导航时必须确保没有残留的 `slam_toolbox` 在跑，否则它会和重定位节点抢同一个 TF（见 [运行文档 §6.9](运行文档.md)）。
>
> 重定位节点的 `map→odom` 时间戳打到 `now + 0.2 s`（`tf_future_stamp`），保证 Nav2 用“当前时刻”查 TF 时不会报 extrapolation into the future。

### 6.2 速度控制链

```
controller_server ──/cmd_vel_nav──► velocity_smoother ──/cmd_vel──► diff_drive
behavior_server(恢复) ─────────────────────/cmd_vel──► diff_drive
```

### 6.3 一次导航数据流

```
RViz 2D Nav Goal ──► bt_navigator ──► planner_server ──► 全局路径
                                                              │
                                          controller_server(MPPI) ◄── local_costmap
                                                              │
                              /cmd_vel_nav ──► velocity_smoother ──► /cmd_vel ──► diff_drive
                                                              │
                              轮子转 ──► /livox/lidar + /livox/imu ──► FAST-LIO ──► /Odometry + odom→base_link
                                                              │                    /cloud_registered
                                                              ▼
                              fastlio_relocalization（对 prior_3d_map.pcd 做 ICP）──► map→odom
                              /scan ──► 代价地图更新 ──► 直到到达
```

更完整的话题速查表与数据流图见 [architecture.md §9](architecture.md)。
